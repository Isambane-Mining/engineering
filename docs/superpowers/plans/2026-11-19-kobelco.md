# Kobelco Integration Implementation Plan

**Goal:** Implement the user's manual, read-only Kobelco integration in LAB on branch `juan`.
**Architecture:** Native singleton API Kobelco Settings, embedded Kobelco Machine Mapping child table, immutable Kobelco Results snapshots, isolated controller. Explicit Asset selection, no automatic matching or Asset creation. Use WearCheck form/list/workspace patterns without changing its code.
**Tech stack:** Frappe, requests HTTP Basic Authentication, unittest and LAB database validation.
**Spec:** User request in this session (2026-11-19).

## Constraints
- Preserve existing dirty files; only append Kobelco navigation to the current workspace.
- No branches, commits, pushes, production operations, scheduler, MPI/WearCheck changes or outbound API writes.
- Password field uses Frappe encryption. Credentials never appear in errors or result payloads.
- Serial, PIN and Asset mapping uniqueness enforced in DB and controller; model is descriptive only.
- Missing optional telemetry stays empty; retain source timestamps and units in raw JSON.

## Tasks
- [x] 1. Write mocked-HTTP automated tests for authentication, base-path-safe pagination, malformed responses, transport errors and telemetry normalization. Run RED, implement client/parser, run GREEN.
- [x] 2. Write LAB transaction tests for mapping uniqueness, unmapped discovery, snapshot deduplication, relinking, permissions, disabled integration and failure rollback/status. Run RED, implement schema/controllers, run GREEN.
- [x] 3. Add native forms/lists and additive workspace navigation. Reload only the three new DocTypes and Engineering workspace in LAB, avoiding a full migration that would apply unrelated dirty patches/fixtures.
- [x] 4. Run new tests, existing controller regressions, Python/JS/JSON validation and review all changes. Verify original unrelated files against starting hashes and workspace against its initial structure. Record results and every added file in integration documentation.

## Review focus
- Base path loss, cross-origin pagination, redirect credential leakage and loops.
- Mixed/missing/zero measurements and timestamps, independent serials sharing one model.
- Same data fetched twice, concurrent fetches, duplicate serial/PIN/Asset, conflicting identifiers.
- Mapping after import, clearing a mapping, unauthorized endpoint access, failed partial import.
- Isolation from existing Asset, Machine File, Equipment, WearCheck, MPI and scheduler behavior.

## Execution
Inline implementation, as requested. No additional approval or commits. Schema activation is limited to the new DocTypes to preserve unrelated LAB work. Interfaces: the parser returns normalized machine dictionaries consumed by discovery and sync; mapping updates relink existing snapshots. Tests will exercise these interfaces together.
